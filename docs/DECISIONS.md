# Decisions taken while the owner is away

Format: what, why, alternatives. Newest at the bottom.

1. **Checklist area = ID prefix; "Done" = every line ticked.** Counted by `tools/checklist_status.py`. Why: the owner asked for a truthful, reproducible status. Alternative: manual counts (error-prone, rejected).
2. **LinkedIn-dependent lines carry `[LV:mock]` or `[LV:real]`.** Why: separate "tested on the mock site" from "verified on real LinkedIn". Alternative: a separate document (would drift).
3. **Real LinkedIn is not touched while the owner is away.** The six read-only tests stay in `docs/reports/real-linkedin-read-only-plan.md`.
4. **withdraw_invite got its own hard ceiling of 20 a day.** Why: every action type needs one, and withdrawing is a LinkedIn action. The agreed-ceilings test now lists it.
5. **New API keys are read-only by default; keys without a recorded scope are read-only.** Why: least privilege; an old key silently losing write access is safer than one gaining it. Alternative: treat old keys as read and write (rejected).
6. **Webhooks connect to the checked IP address and refuse redirects.** Why: stops DNS rebinding and redirect SSRF. Alternative: re-resolve at call time only (leaves a small rebinding window).
7. **Rate limit is in memory, 60 a minute per key.** Why: simplest correct limit for one API process; recorded as a limit in the security review for multi-process hosting.
8. **The real typecheck is `npm run typecheck` (tsc -b).** An earlier habit of running `tsc --noEmit` at the project root checked nothing (the root tsconfig lists no files), so reports of "typecheck passes" for areas 5 to 10 were wrong. 28 real errors (zod 4 `z.record` needs two arguments, a Switch missing a prop) were fixed on 16 Nov 2026 and `tsc -b` now passes. Every later report states the exact command.
9. **Manual reactions and comments have their own hard ceiling of 25 a day (`engage_post`).** Why: every LinkedIn action needs one; a hand-made action still reaches LinkedIn. The comment is the person's own text; Synex never writes it while sending.
10. **Phase 2 (match OutFlo) decisions, 19 Nov 2026.** (a) Keep Synex's teal design and dark mode; copy OutFlo's structure and wording, not its colours. (b) Accounts list gets OutFlo's table as the default, cards stay as a second view. (c) Lead lists get a "Lead List Management" card on Others like OutFlo; the top-level Leads page stays (it is richer). (d) New accounts still start at limit 0 and our hard ceilings stand; OutFlo's 25/30 defaults are not copied. (e) The Smart sequence view becomes a React Flow canvas (`@xyflow/react`, MIT); the step data model and server rules do not change. Why: closest to OutFlo without breaking the safety rules or our extras. Alternative: restyle everything toward OutFlo (rejected; the brief fixes Synex's design).
11. **Correction to the Phase 1 comparison:** Synex already has all 11 OutFlo node types in its model (voice note, InMail, free InMail, follow, like, view profile, withdraw, If connection, Is active); only the view was a stacked list. The "Action Allocation" row needs a re-check against `allocation` in the campaign model.
12. **The campaign wizard unlocks strictly in order, and the stepper says so.** Steps: 1 sender, 2 leads (a list with at least one lead), 3 sequence (every node ready), 4 review. A later step is locked (lock icon, disabled, "Finish step N first"); finished steps show a tick; the line between steps fills as they complete. Review also stays locked while a Smart node is not ready (before, only Next was off). Why: the owner said the order must be forced, as OutFlo does. Saving a draft is allowed at any step. Alternative: let people jump freely and gate only the launch (rejected by the owner).
13. **Gaps from the OutFlo comparison that were NOT built, and why (19 Nov 2026).** (a) Rewards page: OutFlo's is a marketing referral programme; Synex has no programme, so a page would be an inert control. (b) Per-campaign "Configure webhook": needs a new campaign field, delivery code and migration; kept for the next pass, workspace webhooks already exist. (c) Account location and company in the header: the profile sync does not read them yet; showing empty fields would be dishonest. (d) "Connect via Extension": the Chrome extension does not exist yet (brief: comes later); it will appear as a disabled "Coming soon" option when the connect options are reworked. Lead variables, Action Allocation, What's new and timezone already existed.
14. **Settings got one left menu** (Profile and assistant, Integrations, Notifications, Usage, Safety, Support), as OutFlo has; the pages themselves are unchanged. The account page got a banner behind the avatar.
15. **Meet Affix limits raised by the owner (25 Nov 2026).** The owner asked for "normal good limits". Set to OutFlo's defaults, each inside Synex's hard ceilings: connection requests 25 (and 150 a week), messages 30, profile views 25, follows 25, connection checks 30, inbox reads 48, withdraw invites 20, likes 25, InMails 15, voice notes 10, lead pages 10, connection-list reads 6, manual reactions 10; daily variation ±2; overall 150 a day (ceiling 200). This replaces the earlier test rule of at most 5 visits, 5 requests and 5 messages a day. Hard ceilings, warm-up and the stop-on-warning rule are unchanged. Inbox replies are no longer paced like campaign work (decision in the inbox commit bd21171), but still count against these limits.
